= C4 Level 3 - Components

== Overview
The component diagram shows how the FHS Python Library is decomposed into DDD layers.
Dependency direction is always top-down: Presentation -> Application -> Domain/Core -> Infrastructure.

== Component Responsibilities

=== Presentation Layer

==== Notebook Facade (`fhs.notebook`)
* Exposes `load_scenario(name, editable=False)` as the single notebook entry point
* Exposes `notebook_setup()` for one-line environment configuration (matplotlib, warnings, style)
* Shows interactive configuration form when `editable=True` (ipywidgets)
* Contains no business logic — only orchestration and display delegation

==== Widget Display (`fhs.presentation.notebook.widgets`)
* `show` singleton facade with mixin-based API: `show.simulation()`, `show.comparison()`, `show.risk_dashboard()`, …
* Delegates rendering to Charts module and applies Styling & Formatting
* Mixins: `_PrimitivesMixin`, `_CapitalBudgetingMixin`, `_RiskMixin`, `_PortfolioMixin`, `_DistributionMixin`, `_DeliveryMixin`
* Includes table builders for metrics, decisions, risk analysis, comparisons, and sample data

==== Charts (`fhs.presentation.notebook.charts`)
* Matplotlib and Plotly chart builders: portfolio distributions, risk profiles, fan charts, heatmaps
* Modules: `portfolio.py`, `risk.py`, `forecast.py`, `distributions.py`, `capital_budgeting.py`, `heatmap.py`
* All charts use the centralised `COLORS` palette and `setup_style()` configuration

==== Styling & Formatting (`fhs.presentation.notebook.styling`)
* `COLORS` palette, `palette()`, `setup_style()` — consistent visual design
* `formatters.py` — risk metric and delivery analysis formatters
* `template_engine.py` — HTML template rendering for widget cards

=== Application Layer

==== Scenario Service
* Calls YAML Repository to load and validate scenario files
* Assembles typed `ScenarioContext` objects consumed by notebooks
* Publishes `ScenarioConfigurationChanged` domain events on save

==== AdvancedPortfolioService (main facade)
* Accepts features, budget, discount rate, seed, and scenario count
* Exposes five domain sub-facades via `service.risk`, `service.delivery`, `service.multi_year`, `service.decisions`, `service.layers`
* Delegates all computation — contains no calculation logic itself
* All collaborators share an explicit `PortfolioContext` Protocol (no `host: Any`)

==== Sub-Facades
[cols="1,3"]
|===
| Sub-facade | Responsibility

| `service.risk`
| Loss metrics, Shapley attribution, component-level simulated risk

| `service.delivery`
| Delivery risk simulation, sprint overrun stress tests, profitability analysis

| `service.multi_year`
| Multi-year Monte Carlo P&L, NPV/IRR, financial views per feature

| `service.decisions`
| Feature ranking, score analysis, strategy category cost share

| `service.layers`
| Risk layer simulation, feature sensitivity, risk retention
|===

==== Case Study Service
* Orchestrates the blockchain case study across notebooks
* Provides board recommendation generation
* Delegates to AdvancedPortfolioService for portfolio analysis

==== Export Service
* Exports portfolio results and risk reports to Excel/CSV
* Delegates formatting to infrastructure exporters

==== Service Factory
* Factory pattern for creating and wiring all application services
* Ensures consistent dependency injection across the application layer

=== Domain Layer

==== Domain Models (`fhs.core.model`)
* `Feature` — Pydantic aggregate root with `business_value` distribution parameters
* `SimulationResult` — VaR, CVaR, expected value, scenario array (25+ computed properties)
* `MultiYearResult` / `YearResult` — per-year simulation output
* Value objects: `BudgetFrontier`, `OptimizationResult`, `RiskLayerStats`, `ShapleyAttribution`, `PortfolioSnapshot`, `LossMetrics`, `FinancialView`, …

==== Domain Events
* `ScenarioConfigurationChanged` — published when scenario config is saved
* `EventBus` — simple in-process event routing
* `EventLogger` — writes audit trail to `notebooks/logs/`

==== Scenario Config
* `ScenarioConfig` — aggregate for scenario-level parameters
* `DeliveryRiskConfig` — delivery risk simulation parameters (scenarios, failure rates)

==== Repository Interfaces
* `FeatureRepository` protocol — defines persistence contract
* Implemented by `YamlFeatureRepository` in infrastructure layer

==== Domain Exceptions
* `FHSException` — base exception
* `SimulationError`, `ValidationError`, `PortfolioOptimizationError`, `CorrelationMatrixError`, `InsufficientDataError`

=== Core Domain Services

==== Monte Carlo Engine
* Generates scenario distributions (Normal, Lognormal, Beta)
* Supports bounded sampling and correlated draws via Cholesky decomposition
* Returns raw `np.ndarray` scenario arrays

==== Risk Calculator
* VaR and CVaR at configurable confidence levels
* Bootstrap confidence intervals for tail metrics
* Shapley attribution of portfolio risk to individual features
* Delivery risk: loss metrics, LaR computation

==== Portfolio Service
* Aggregates per-feature simulations into portfolio-level risk
* Computes correlation matrix and concentration (Herfindahl index)
* Budget frontier generation via ILP/SLSQP solvers
* Stress testing and scenario analysis

==== Optimization Service
* ILP (Integer Linear Programming) exact solver for budget allocation
* CVaR-MILP solver for risk-constrained optimisation
* Greedy fallback solver for large feature sets
* Supports `var_floor` and `value_max` optimisation strategies

==== Simulation Engine
* `FeatureSimulator` — main orchestration for single-feature Monte Carlo
* Multi-year simulation with growth rate compounding
* Multi-year P&L computation across portfolio

==== Assessment & Ranking
* `FeatureAssessmentService` — feature-level risk and value assessment
* `RankingService` — ranking strategies: Expected Value, VaR, CVaR, ROI

==== Financial Calculator
* Present value, NPV, IRR, annualisation computations
* Used by multi-year operations for financial views

==== Reporting Service
* Executive summaries for board-level reporting
* Stress test reports with scenario analysis
* PO summary generation
* Year 1 delivery risk reports

=== Infrastructure Layer

==== YAML Repository
* Reads and writes `notebooks/config/*.yaml`
* Materialises `Feature` entities, `ScenarioConfig`, and `DeliveryRiskConfig` from YAML
* Implements the `FeatureRepository` protocol defined in the domain

==== Portfolio Exporter
* Excel export with styled worksheets (openpyxl)
* Formats portfolio results, risk metrics, and optimisation outputs

==== Versioning Service
* Tracks scenario configuration version history
* Supports rollback to previous configurations

==== Simulation Config
* `DEFAULT_CONFIG` — default simulation parameters
* Logging configuration via `configure_logging()`
* Validation defaults for simulation inputs
